# flaky

`flaky` is an offline single-binary CLI tool that repeats a test command, parses standard JUnit XML reports, ranks intermittent failures, and bisects their statistical introduction along git first-parent history.

---

## Features

- **Offline & Zero Dependencies**: Runs as a single self-contained binary written strictly with the Go standard library.
- **Runner Agnostic**: Consumes standard JUnit XML generated by pytest, gotestsum, Jest, cargo-nextest, Maven, Gradle, or custom test runners.
- **Isolated Execution**: Commands run in isolated temporary copies of the repository; parallel scan workers never share filesystems or race on artifacts.
- **Safe Git Bisect**: Samples first-parent history using temporary detached worktrees without resetting, modifying, or dirtying the active working branch.
- **Statistical Rigor**: Uses 90% two-sided Wilson score confidence intervals to classify commits as stable, flaky, or inconclusive (exiting cleanly on ambiguity rather than guessing).
- **Process Safety**: Gracefully terminates child process groups on timeout or Ctrl-C interrupt (exit code 130) with guaranteed workspace cleanup.

## Quickstart

### Installation

Install via Go:
```sh
go install github.com/dpologdvinity/flaky/cmd/flaky@latest
```

Or build directly from source:
```sh
git clone https://github.com/dpologdvinity/flaky.git
cd flaky
go build -o flaky ./cmd/flaky
```

### Basic Commands

```sh
# Scan tests with 20 runs (default)
flaky -- pytest tests/

# Scan tests with 30 runs across 4 parallel workers
flaky -n 30 --parallel 4 -- pytest tests/

# Output machine-readable JSON
flaky -n 20 --json -- gotestsum -- ./...

# Bisect a specific test across git history
flaky bisect pkg::test_a --runs 30 -- pytest tests/
```

## CLI Reference

### 1. Scan Mode (Default)
```
flaky [-n N] [--parallel P] [--junit RELPATH] [--json] -- COMMAND [ARG...]
```

| Flag | Default | Description |
|---|---|---|
| `-n`, `--runs` | `20` | Number of test repetitions ($1 \le N \le 1000$). |
| `--parallel` | `1` | Number of concurrent worker copies. |
| `--junit` | (Auto) | Relative path to fixed JUnit XML written within workspace. |
| `--json` | `false` | Output structured JSON instead of formatted text table. |
| `--` | Required | Separator preceding the test command. |

### 2. Bisect Mode
```
flaky bisect TEST-ID [--runs N] [--junit RELPATH] [--json] -- COMMAND [ARG...]
```

| Flag | Default | Description |
|---|---|---|
| `TEST-ID` | Required | Canonical test ID (`classname::name` or `file::name`). |
| `--runs` | `30` | Repetitions per sampled commit ($N \ge 30$). |
| `--junit` | (Auto) | Relative path to fixed JUnit XML written within workspace. |
| `--json` | `false` | Output structured JSON instead of formatted text. |
| `--` | Required | Separator preceding the test command. |

*Note: Parallelism is not supported in bisect mode to maintain linear git worktree isolation.*

## JUnit Setup & Runner Adapters

`flaky` passes a unique absolute report path as `FLAKY_JUNIT_XML` and a 1-based `FLAKY_RUN_INDEX` environment variable to every execution.

If your runner expects an explicit argument, `flaky` provides automated adapters or accepts `--junit RELPATH`:

| Runner | Example Invocation | Adapter Mechanism |
|---|---|---|
| **pytest** | `flaky -- pytest tests/` | Automatically appends `--junitxml=$FLAKY_JUNIT_XML`. |
| **gotestsum** | `flaky -- gotestsum -- ./...` | Inserts `--junitfile=$FLAKY_JUNIT_XML` before gotestsum's `--`. |
| **Jest + jest-junit** | `flaky -- jest` | Sets `JEST_JUNIT_OUTPUT_DIR` and `JEST_JUNIT_OUTPUT_NAME`. |
| **cargo-nextest** | `flaky --junit target/nextest/default/junit.xml -- cargo nextest run` | Nextest writes relative to workspace via `.config/nextest.toml`. |
| **Custom Script** | `flaky --junit reports/junit.xml -- ./test.sh` | Reads from the specified relative report path. |

> [!IMPORTANT]
> The JUnit report must remain strictly inside the temporary workspace and cannot be a symlink pointing to an outside file.

## Statistical Methodology

$$\text{Failure Rate} = \frac{\text{Failures}}{\text{Passes} + \text{Failures}}$$

- Tests absent from a run or marked skipped do not enter the denominator.
- A test is classified as **flaky** only if both a pass and a failure are observed across runs.
- **Wilson Score Interval (90% Confidence)**: Used during bisect to determine whether failure frequency indicates true flakiness:
  - **Stable**: Upper confidence bound $< 10\%$.
  - **Flaky**: Passes $> 0$, Failures $> 0$, and Lower confidence bound $> 10\%$.
  - **Inconclusive**: Neither condition met (triggers exit code 3).

## Exit Codes

| Code | Meaning |
|:---:|---|
| `0` | Success / run completed normally. |
| `1` | Target test ID absent from all sampled reports during bisect. |
| `2` | Command line usage error, missing arguments, or execution failure. |
| `3` | Inconclusive statistical sampling during bisect. |
| `130` | Interrupted by signal (`SIGINT` / Ctrl-C); resources cleaned up. |

## How It Differs

- **vs. `pytest-flakefinder`**: `flaky` supports any language or runner outputting JUnit XML, computes confidence intervals, displays diffs between failing and passing runs, and performs automated git bisection.
- **vs. Cloud CI Services (Trunk, BuildPulse)**: `flaky` is an offline local CLI that does not require cloud accounts, webhooks, or telemetry uploads.
